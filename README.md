# 06-shiftboard（交班台）

交班台 — 班次责任与在途批次交接：班次登记 → 在途批次归属 → 交班互斥办理 → 交班前后对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流，**不是** 质检签发，**不是** 数仓贴源/明细/汇总分层。  
**也不是** OA 考勤排班后台、电商订单、报表 CSV 看板。

## 启动

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=%CD%\data
set FIXTURES_DIR=%CD%\..\fixtures
uvicorn app.main:app --host 127.0.0.1 --port 10600

# 前端
cd frontend
npm install
npm run dev
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://127.0.0.1:5600 |
| 接口 | http://127.0.0.1:10600 |

## 主链

登记班次与值班人 → 在途批次归属当前班次 → 发起交班（清单批次进入**托管态**：独立托管表挂交班单，两侧在途均不计入，全仓同时仅一单进行中）→ 完成则整单出托管过户接班方 / 取消或失败则整单出托管退回交班方（同一事务切换，禁止部分残留）→ 发起与出口两笔同源对账报告

### 托管规则

- 落库形态：独立 `escrow_batches` 表（挂交班单 id，与在途物理隔离可查）+ 批次状态机 `在途 → 托管中 → 在途` 双保险
- 托管期内禁止结清、改归属、再次进入别的交班清单；冲突报错写明托管交班单号
- 出口一致性：出口前先校验清单与托管集合完全一致，随后同一事务切换全清单，任一不符整体回滚
- 对账可解释「发起时在途减少、完成时接班方增加、失败时交班方恢复」，数字与托管集合、在途集合、交班单同源

## 界面约定

页面文案全部中文；入口：总览 / 班次 / 在途批次 / 交班办理 / 交班记录 / 交班对账。
